# Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Шаг 5 из §9 спеки: `GET /health` и `PostgresProvider.ping()`, рабочий `server.endpoint`, удаление мёртвых полей и `--workers`, скрипт `postgres-fastmcp`, версия `0.1.0`, README, `env.example`, `docker/config.json`, `AGENTS.md`; плюс follow-up шагов 3–4: префиксы env, CLI-флаги без `--database-uri`, `DatabaseConfig` без env для библиотеки, `Settings` без чтения `AUTH`/`DATABASE`/..., ruff на тестах.

**Architecture:** План по спеке `docs/superpowers/specs/2026-09-26-auth-fastmcp4-hardening-design.md` (§1.2 п.4–5, §3.2 `ping()`, §3.7 п.4 и `main.py` `path=`, §5 целиком, `/health` в §8) поверх `main` `48a73cf` (шаги 1–4 влиты). Сначала чинится загрузка конфигурации (Task 1–3), потому что на ней стоят `endpoint`, `/health` и переименование префиксов: `Settings` перестаёт читать env сам и отдаёт это вложенным блокам; `DatabaseConfig` становится обычной pydantic-моделью, а чтение `MCP_DATABASE_*` уходит в подкласс `DatabaseSettings`; CLI передаёт в `Settings` только явно заданные флаги и накладывает их на секции `config.json` поле за полем. Потом `endpoint` (Task 4) и `/health` (Task 5), затем видимые оператору переименования (Task 6–7), документация (Task 8), ruff на тестах (Task 9), опциональный таймаут CI (Task 10) и полная проверка (Task 11).

**Tech Stack:** Python 3.12+, uv, FastMCP 4.0.10, pydantic 2.13.4, pydantic-settings 2.14.2, cyclopts, psycopg 3 / psycopg-pool, pytest + pytest-asyncio (asyncio_mode=auto) + pytest-timeout 2.4.0, ruff 0.15.21 (select=ALL), mypy 2.3.0 strict.

## Global Constraints

- Язык: всё, что видит агент или внешняя система (описания тулов, `instructions` сервера, сообщения ошибок и валидации, тело ответа `/health`, логи, коммиты), пишется на английском. По-русски только комментарии и docstring, которые видит лишь разработчик. README — русская пользовательская документация.
- Нигде нет `from __future__ import annotations`.
- Перед каждым коммитом: `uv run ruff check --fix --show-fixes`, `uv run mypy src/`, `uv run ruff format` — все три с нулём ошибок; плюс `uv run ruff format <изменённые файлы тестов>` по путям (до Task 9 `tests` исключены из ruff в `pyproject.toml`, явно переданный путь всё равно форматируется; после Task 9 тесты входят в `ruff check .`/`ruff format .`).
- `<env>` ниже означает `MCP_DATABASE_HOST=localhost MCP_DATABASE_PORT=5432 MCP_DATABASE_USER=u MCP_DATABASE_PASSWORD=p MCP_DATABASE_NAME=d FASTMCP_MCP_CAMELCASE_COMPAT=false`. Юнит-тесты: `<env> uv run pytest tests/unit -q`. Базовая линия до плана: `866 passed`.
- Docker локально недоступен: `<env> uv run pytest tests/integration -q` только собирает и пропускает тесты (до плана `94 skipped`). CI гоняет их на Postgres 15 и 16. Интеграционные правки проверяются статически: сбор без ошибок и `uv run ruff check <файл> --select F,ARG --no-fix`.
- Ломающие изменения разрешены, легаси не сохраняется: старые имена переменных, `--workers`, скрипт `postgres-mcp` не поддерживаются даже предупреждением.
- Субагенты никогда не запускают `git config` и `git stash` (в репозитории есть чужая старая запись stash — не применять и не удалять).
- Работа идёт в текущей ветке `claude/cleanup`. Отдельных веток, push и PR в плане нет; последняя задача — полная локальная проверка CI, включая stdio end-to-end и HTTP `/health`.
- Формат коммитов: `type(scope): message`, повелительное наклонение, английский.
- Секреты не утекают: ответ `503` на `/health` маскирует пароль БД (строки подключения, `password=...`, сам пароль и его URL-форма); дамп настроек нигде не отдаётся; пароль из `--database-uri` остаётся `SecretStr`.
- Инварианты шагов 1–4: при `auth.mode=none` поведение и `tools/list` те же (размер `tools/list` FULL = 9710 символов); `ResponseBudgetMiddleware` первым middleware; тесты auth, бюджета, кириллицы и схемы проходят без изменений (кроме переименования переменной `MCP_RESPONSE_MAX_TOKENS` в Task 6).
- Если меняется префикс env или имя скрипта — синхронно обновляются CI, `Dockerfile`, `docker/config.json`, `env.example`, README; каждое старое имя ищется `grep` (шаги в Task 6, 7, 11).

## Проверено на установленных версиях (FastMCP 4.0.10, pydantic 2.13.4, pydantic-settings 2.14.2, cyclopts, psycopg 3)

Справка для исполнителя; каждое утверждение проверено экспериментом или чтением кода `.venv/lib/python3.12/site-packages`. Весь план прогнан в отсоединённом `git worktree` (scratchpad) против `.venv` проекта (`PYTHONPATH=<worktree>/src`, без `uv sync`): числа тестов ниже — реальные. После прогона worktree удалён, editable-установка указывает на репозиторий.

- **`custom_route` и auth.** `FastMCP.custom_route(path, methods, name=None, include_in_schema=True)` (`fastmcp/server/mixins/transport.py:131`) кладёт Starlette `Route` в `_additional_http_routes`. `create_streamable_http_app` (`fastmcp/server/http.py`) оборачивает в `RequireAuthMiddleware` **только** MCP-маршрут, а свои маршруты добавляет следом без обёртки; `AuthenticationMiddleware` провайдера лишь заполняет `request.user` и не отклоняет запрос. Проверено через `asgi_server` со `StaticTokenVerifier(required_scopes=["mcp"])`: `GET /health` без токена — `200`, `POST /mcp` без токена — `401`. `HEAD /health` — `200` (Starlette добавляет HEAD к GET), `POST /health` — `405`.
- **`path` и ведущий `/`.** `mcp.run(transport="http", path=...)` → `run_http_async(path=...)` → `http_app(path=...)`; без `path` берётся `fastmcp.settings.streamable_http_path = "/mcp"`. `http_app(path="mcp")` падает `AssertionError: Routed paths must start with '/'`, поэтому текущее значение по умолчанию `server.endpoint = "mcp"` уронило бы HTTP-старт, если просто передать его в `run`. `/health` всегда в корне: у `http_app(path="/api/mcp")` маршруты `['/api/mcp', '/health']`.
- **`asgi_server` и URL.** `ASGIServer.url` включает путь (`http://127.0.0.1/mcp`), и `http_client()` использует его как `base_url`: относительный `"/health"` превращается в `/mcp/health` (404). Тесты берут абсолютный `http://127.0.0.1/health`.
- **Пинг через пул не годится для `/health`.** `SqlExecutor(conn=DbConnPool(url)).execute("SELECT 1")` на закрытый порт: пул psycopg ретраит соединение в фоне, `pool.connection()` ждёт 30 с, и `asyncio.wait_for(..., 2)` отдаёт пустой `TimeoutError` — настоящая ошибка видна только в логе пула, а сам пул остаётся открытым и ретраит. `psycopg.AsyncConnection.connect(url)` на тот же порт сразу (0.0 с) бросает `OperationalError: connection failed: connection to server at "127.0.0.1", port 1 failed: Connection refused ...`. Поэтому `ping()` открывает отдельное соединение.
- **`Settings` без `env_prefix` читает блоки из env целиком.** С пустым префиксом источник env `Settings` ищет переменные с именами полей: `AUTH=basic` → `SettingsError: error parsing value for field "auth" from source "EnvSettingsSource"` (старт падает), `DATABASE='{"host": "evil"}'` → подключение к `evil`, `SERVER='{"port": 1}'` → порт 1, `FASTMCP=x` → `SettingsError`. `.env` сам `Settings` не читает (нет `env_file`). `settings_customise_sources`, возвращающий `(init_settings,)`, убирает это; вложенные блоки (`default_factory`) и словарь из `config.json` по-прежнему дополняются из своего env (`MCP_PORT`, `MCP_DATABASE_ACCESS_MODE`, `MCP_AUTH_ACCESS_POLICY__ENFORCED` — проверено). `settings_customise_sources` вызывается с именованными аргументами (`env_settings=...`), поэтому сигнатура повторяется целиком.
- **`DatabaseConfig(BaseSettings)` читает env при любом способе создания.** И `DatabaseConfig(host=...)`, и `DatabaseConfig.model_validate({...})` берут `access_mode`/`write_mode` из `MCP_DATABASE_*` — пути «без env» без изменения кода нет. Разделение `class DatabaseConfig(BaseModel)` + `class DatabaseSettings(DatabaseConfig, BaseSettings)` работает: MRO `DatabaseSettings → DatabaseConfig → BaseSettings → BaseModel`, поля и валидаторы наследуются, `DatabaseSettings.from_uri` возвращает `DatabaseSettings`, `isinstance(DatabaseSettings(), DatabaseConfig)`. `model_config` подкласса перекрывает `extra="forbid"` родителя на `extra="ignore"`.
- **Поле `Settings.database`.** Если его тип `DatabaseSettings`, то `Settings(database=DatabaseConfig(...))` падает `Input should be a valid dictionary or instance of DatabaseSettings`. Поэтому тип поля — `DatabaseConfig`, `default_factory=DatabaseSettings`, а `field_validator("database", mode="before")` превращает словарь в `DatabaseSettings(**dict)` (env дополняет). Ошибка изнутри валидатора выглядит как `database: Value error, Database connection URL is not set.` — без `input_value` и без пароля (проверено).
- **CLI на `48a73cf`** (прогон настоящего `main()` с подменённым `create_server`):

## Решения там, где спека открыта

- **Префикс env — `MCP_<СЕКЦИЯ>_<ПОЛЕ>` (follow-up 1).** `ServerSettings` → `MCP_SERVER_`, `FastMCPSettings` → `MCP_FASTMCP_`, как уже у `MCP_DATABASE_` и `MCP_AUTH_` и как обещают README/`env.example`. Правило одно и совпадает с секциями `config.json`. Альтернатива (оставить `MCP_` и переписать документацию) хуже: два блока делят один префикс, `MCP_SERVER_NAME` — это поле `fastmcp`, а не `server`.
- **`Settings` читает только аргументы конструктора (follow-up 4)** через `settings_customise_sources`; env и `.env` читает каждый вложенный блок сам.
- **`DatabaseConfig` без env (follow-up 3).** `DatabaseConfig(BaseModel, extra="forbid")` — для кода библиотеки: только переданное, опечатка или старое поле `role` — ошибка. `DatabaseSettings(DatabaseConfig, BaseSettings)` — чтение `MCP_DATABASE_*` и `.env` (`extra="ignore"`). `Settings.database` принимает оба: словарь → `DatabaseSettings`, готовый `DatabaseConfig` — как есть. `DatabaseSettings` не экспортируется из корня пакета (список §6 не меняется), доступен как `postgres_fastmcp.app.config.database.DatabaseSettings` и через `Settings().database`.
- **CLI (follow-up 2).** Все опции `None` по умолчанию = «не задано»; действует каждая заданная, с `--database-uri` или без. Приоритет: явный флаг > `config.json` > env/`.env` > по умолчанию. Флаги накладываются на секции `config.json` поле за полем. `--database-uri` задаёт только то, что в URI есть (`DatabaseConfig.uri_fields`): URI без пароля берёт пароль из `MCP_DATABASE_PASSWORD` — так пароль не светится в `ps`. Добавлен `--no-write-mode` (побочный эффект `bool | None` в cyclopts): принудительно read-only поверх env.
- **`server.endpoint`**: значение по умолчанию `"/mcp"`, валидатор добавляет ведущий `/` (`"mcp"` из старых конфигов не роняет старт) и срезает пробелы.
- **`ping()` открывает отдельное соединение**, а не берёт его из пула: настоящая ошибка сразу, а не пустой таймаут через 2 с; проба `/health` не открывает пул с `min_size` соединений на сервере без запросов и не оставляет ретраящий пул при лежащей БД. Цена — одно короткое соединение на пробу. `connect_timeout=2` (минимум libpq), общий таймаут 2 с ставит маршрут через `asyncio.timeout`.
- **`/health` регистрирует `create_server`**, а не `main.py` и не `PostgresProvider`: провайдер не сервер, а библиотечный `create_server` должен вести себя как CLI. `include_in_schema=False`. Текст `503`: `obfuscate_password` плюс замена самого пароля и его `quote_plus`-формы на `****`; при таймауте — `database did not answer within 2 s`; неудача пишется в лог на `DEBUG` (пробы каждые несколько секунд не засоряют лог). `PostgresProvider.ping()` публичный, без своего таймаута (ruff `ASYNC109` запрещает параметр `timeout` у async-функций).
- **`FastMCPSettings.instructions` по умолчанию переводится на английский** — это текст для агента.
- **`docker/config.json`**: удаляется `"_comment"` (ронял старт), предупреждение о тестовых паролях переезжает в `docker/README.md`; добавляются `response_max_tokens` и блок `auth`. Регрессионный тест загружает файл.
- **Имя образа в `Makefile`** (`NAME ?= postgres-mcp`) и `LABEL ...title` в `Dockerfile` — тоже `postgres-fastmcp`.
- **ruff на тестах (follow-up 5)** — включить: убрать `tests` из `exclude`, добавить в `per-file-ignores` для `tests/*` правила, которые в тестах шумят по делу (`ARG002`, `S104`, `S106`, `FBT001`, `RUF012`, `PLR0913` — по аналогии с уже игнорируемыми `ARG001`, `S105`), три `RUF043` исправить (`r"..."`), `PT012` и `N802` закрыть точечным `noqa` с причиной, `ANN401` исправить (`param: object`), остальное — автофикс и `ruff format`.
- **Таймаут CI (follow-up 6)** — отдельная опциональная Task 10, рекомендуется.
- **Отложенные изменения поведения (follow-up 7)** в план не входят — см. «Вопросы», п.1.
- **Регрессионный тест упаковки** `tests/unit/test_packaging.py`: имя скрипта и версия читаются из `pyproject.toml`.

## Вопросы к пользователю до исполнения

1. **Отложенные изменения поведения.** `execute_sql` после `INSERT/UPDATE` без `RETURNING` пишет «0 rows.», а `get_object_details` называет таблицу без колонок «не найдено».
```python
    @staticmethod
    def uri_fields(uri: str) -> dict[str, Any]:
        """Поля подключения из URI (postgresql:// или postgresql+asyncpg://).

        Возвращает только то, что в URI есть: host, port (5432, если не указан), user, password,
        name, а из query string — sslmode и client_encoding. Отсутствующее (например пароль) не
        попадает в словарь, и его дополняют config.json или env. Остальные поля URI не задаёт.
        """
        parsed = urlparse(uri)
        qs = parse_qs(parsed.query)
        candidates: dict[str, Any] = {
            "host": parsed.hostname,
            "port": parsed.port or 5432,
            "user": unquote(parsed.username) if parsed.username else None,
            "password": SecretStr(unquote(parsed.password)) if parsed.password else None,
            "name": (parsed.path or "").lstrip("/") or None,
        }
        fields = {key: value for key, value in candidates.items() if value is not None}
        raw_sslmode = qs.get("sslmode", [None])[0]
        if raw_sslmode in {mode.value for mode in SslMode}:
            fields["sslmode"] = SslMode(raw_sslmode)
        client_encoding = qs.get("client_encoding", [None])[0]
        if client_encoding:
            fields["client_encoding"] = client_encoding
        return fields

    @classmethod
    def from_uri(cls, uri: str, **overrides: Any) -> "DatabaseConfig":
        """Собирает конфиг из URI (postgresql:// или postgresql+asyncpg://).

        Args:
            uri: Строка подключения.
            **overrides: Переопределения полей (write_mode, access_mode и т.д.); проверяются Pydantic при создании.

        Returns:
            Экземпляр DatabaseConfig с заполненными host, port, user, password, name.
        """
        return cls(**{**cls.uri_fields(uri), **overrides})
```

```python
def _merge_sections(json_config: dict[str, Any], overrides: dict[str, dict[str, Any]]) -> dict[str, Any]:
    """Наложить overrides CLI на секции json-конфига поле за полем, а не секцию целиком."""
    merged = dict(json_config)
    for section, values in overrides.items():
        if not values:
            continue
        base = json_config.get(section)
        merged[section] = {**base, **values} if isinstance(base, dict) else values
    return merged


def build_settings_from_cli(  # noqa: PLR0913
    *,
    database_uri: str | None = None,
    transport: str | None = None,
    host: str | None = None,
    port: int | None = None,
    write_mode: bool | None = None,
    access_mode: AccessMode | None = None,
    config_path: Path | None = None,
) -> Settings:
    """Формирование Settings из аргументов CLI (единый источник текущих прав/конфигурации).

    Приоритет: явно заданный флаг > config.json > env/.env > значения по умолчанию. None означает
    «флаг не задан» и ничего не переопределяет. Флаги накладываются на секции config.json поле
    за полем; database_uri задаёт только поля подключения (host, port, user, password, name,
    sslmode и client_encoding, если они есть в URI). JSON-конфиг подхватывается только при
    использовании как CLI: по умолчанию — `./config.json` из CWD; для библиотечного использования
    стройте Settings напрямую или передавайте явный путь.
    """
    json_config = load_json_config(config_path if config_path is not None else Path("config.json")) or {}
    server = {
        key: value for key, value in {"transport": transport, "host": host, "port": port}.items() if value is not None
    }
    database: dict[str, Any] = DatabaseConfig.uri_fields(database_uri) if database_uri else {}
    database.update(
        {
            key: value
            for key, value in {"access_mode": access_mode, "write_mode": write_mode}.items()
            if value is not None
        }
    )
    return Settings(**_merge_sections(json_config, {"server": server, "database": database}))
```

```python
def _mask_password(text: str, password: str | None) -> str:
    """Убрать пароль из текста ошибки: строки подключения, password=..., сам пароль и его URL-форму."""
    masked = obfuscate_password(text) or ""
    if password:
        for form in {password, quote_plus(password)}:
            masked = masked.replace(form, "****")
    return masked


def _add_health_route(mcp: FastMCP, provider: PostgresProvider, password: str | None) -> None:
    """GET /health: 200, если БД ответила на SELECT 1 за HEALTH_TIMEOUT_SECONDS, иначе 503 с ошибкой.

    custom_route не оборачивается в RequireAuthMiddleware FastMCP: маршрут доступен без токена.

    @mcp.custom_route("/health", methods=["GET"], include_in_schema=False)
    async def health(_request: Request) -> JSONResponse:
```

```python
from pydantic import Field, field_validator
from pydantic_settings import BaseSettings, SettingsConfigDict

from postgres_fastmcp.shared.enums import TransportConfig


class ServerSettings(BaseSettings):
    """Настройки сервера: env ``MCP_SERVER_*``, секция ``server``."""

    model_config = SettingsConfigDict(
        env_file=".env", env_prefix="MCP_SERVER_", extra="ignore", hide_input_in_errors=True
    )

    host: str = Field(default="127.0.0.1", description="Хост для привязки сервера")
    port: int = Field(default=8000, description="Порт для привязки сервера")
    transport: TransportConfig = Field(
        default=TransportConfig.HTTP, description="Глобальный тип транспорта: 'http' или 'stdio'"
    )
    endpoint: str = Field(default="/mcp", description="Путь MCP endpoint для HTTP (ведущий '/' добавляется сам)")
    health_endpoint_enabled: bool = Field(
        default=True, description="Включает endpoint проверки состояния /health (авторизация не требуется)"
    )
    response_max_tokens: int = Field(

        ge=1000,
        description="Предел ответа тула в токенах (MCP_SERVER_RESPONSE_MAX_TOKENS); больший ответ заменяется ошибкой",
    )

    @field_validator("endpoint")
    @classmethod
    def _leading_slash(cls, value: str) -> str:
        """Starlette принимает только путь с ведущим '/': 'mcp' из старых конфигов становится '/mcp'."""
        value = value.strip()
        return value if value.startswith("/") else f"/{value}"
```

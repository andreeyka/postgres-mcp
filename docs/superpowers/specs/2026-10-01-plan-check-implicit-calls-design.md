Дата: 2026-10-01. Статус: спроектировано, план — `docs/superpowers/plans/2026-10-01-20-plan-check-implicit-calls.md` (код плана опробован на копии репозитория и живом PostgreSQL 17.10). ## 2. Когда Postgres вызывает машинерию

Проверено на живом PG 17.10 бросающими функциями (PL/pgSQL `RAISE`; функции ввода-вывода и оценки селективности на PL/pgSQL невозможны — `cstring`/`internal`, поэтому там обёртки `LANGUAGE internal`: ввод `int4in` бросает на `'abc'`, вывод `enum_out` — на любом значении, которое не метка перечисления).

| Что | Когда выполняется | Пример (живьём) |
| --- | --- | --- |
| Функция ввода типа | `PREPARE` (разбор константы) | `PREPARE … SELECT 'abc'::app_t` и `PREPARE … INSERT INTO app_tt VALUES ('abc')` — ошибка `int4in` при `PREPARE`, имени типа во втором нет |
| Ввод атрибута составного типа, подтипа диапазона | `PREPARE` (`record_in`, `range_in`) | `'[1,2]'::app_rr` над доменом с `CHECK (VALUE > secret.boom())` — `BOOM` при `PREPARE`; `'{[1,2]}'::app_rr_multirange` — тоже |
| Функция вывода | `EXPLAIN VERBOSE` (печать константы) и выполнение | `EXPLAIN SELECT '5'::app_t` проходит, `EXPLAIN VERBOSE` — ошибка `enum_out` |
| Функция приведения, `IMMUTABLE` | `EXPLAIN` (свёртка) | `SELECT 1::app_e`, `INSERT INTO app_et (e) VALUES (1)` (присваивание) — `BOOM` при `EXPLAIN`; `PREPARE` проходит |
| Функция приведения, `VOLATILE` | выполнение | план печатает `Output: (1)::app_e2` — функции в плане нет |
| `CHECK` домена при приведении | `EXPLAIN` (typcache сворачивает `IMMUTABLE`-вызовы `CHECK` при загрузке ограничений домена) | `SELECT 1::app_rd`, `INSERT INTO app_dt VALUES (5)` — `BOOM` при `EXPLAIN` |
| Опорная функция btree (сравнение) | выполнение; с константами — `EXPLAIN` | `ORDER BY c`, `GREATEST(c, c)` — при выполнении; `GREATEST('1'::app_ct, '2'::app_ct)`, `ARRAY['1'::app_ct] < ARRAY['2'::app_ct]` — при `EXPLAIN` |
| Хеш-функция | выполнение | `DISTINCT`, `GROUP BY`, `UNION` — хеш-агрегат |
| Функции оценки селективности | `EXPLAIN` (планировщик) | по исходникам: `clauselist_selectivity` вызывает `oprrest` каждого условия |

Уточнения к гипотезам задачи:

- **`CHECK` домена при `PREPARE` литерала не выполняется.** `PREPARE … SELECT '1'::app_rd` и `INSERT INTO app_dt (d) VALUES ('5')` проходят: `coerce_type` вводит литерал функцией ввода базового типа и оборачивает `CoerceToDomain`. Сворачивает `CHECK` уже `EXPLAIN`. При `PREPARE` его выполняет только `domain_in` — ввод подтипа диапазона, элемента массива или атрибута составного типа.
- **Представления.** Функцию приведения внутри представления `pg_depend` правила записывает (`secret.int_to_e_imm(integer)`), и её уже закрывает проверка зависимостей. У `SELECT 1::app_rd` в представлении в `pg_depend` только тип `app_rd`. Проверка зависимостей тип пропускает (`public`), и `EXPLAIN SELECT * FROM app_dom_view` выполняет `CHECK` — эта дыра существует и в текущем коде. Опорные функции класса операторов представление не записывает вовсе: у ключа сортировки в `pg_depend` только оператор `<`.
- **`ROW(a) < ROW(b)`** разбор превращает в сравнение по колонкам (`RowCompareExpr`) с оператором `<`, названным по имени. Опорная функция не вызывается, `<` уже проверяется по имени.
- **Результат подготовленного оператора (`pg_prepared_statements.result_types`) не нужен.** Типы результата выводятся из колонок, типов и функций запроса, которые уже есть в семенах (§3), а типы `$N` — из контекста. Константы, которые свернул планировщик, получают тип результата функции, а функция `public` уже даёт свои типы в семена.

## 3. Модель: замыкание типов и строки машинерии

**Семена (типы, до которых доходит оператор).**

- До `PREPARE`, из SQL агента (всех операторов строки, в том числе `PREPARE` агента — он вводит константы при выполнении):
  - имена типов (кроме `pg_catalog.*`), разрешённые `pg_catalog.to_regtype` по `search_path`, как их разрешит `PREPARE`;
  - типы колонок названных отношений и представлений: `pg_catalog.to_regclass` → `pg_attribute`; имя CTE даёт лишнее семя или ничего;
  - типы аргументов, результатов и `OUT`-аргументов функций `public` и операторов `public`, названных в SQL агента (все перегрузки с именем, как у реализаций), и тип состояния агрегатов `public`.
- В каждом следующем круге реализаций — типы найденных функций `public` (тела, реализации операторов и агрегатов, функции машинерии) и операторов.
- После `PREPARE` и после всех `EXPLAIN`: типы колонок отношений `relations` запроса определений — заблокированные, цели DML, их потомки — и типы из `pg_depend` определений (`types`: правила, CHECK, индексы, триггеры и прочее).

**Замыкание.** От семян — по тому, что вызывает машинерию вложенных типов:

- домен → базовый тип (`typbasetype`);
- массив → элемент (`typelem`);
- составной тип → типы атрибутов (`pg_attribute` по `typrelid`);
- диапазон → подтип (`pg_range.rngsubtype`);
- мультидиапазон → диапазон (`rngmultitypid`).

Типы `pg_catalog` не раскрываются и не проверяются: это встроенная машинерия.

**Машинерия типа** (для каждого типа замыкания вне `pg_catalog`):

| Что | Строка (`kind`) | Правило |
| --- | --- | --- |
| `typinput`, `typoutput`, `typreceive`, `typsend`, `typmodin`, `typmodout`, `typanalyze`, `typsubscript` | `type_function` | функция `pg_catalog` — любая; `public` — проходит, её тело и умолчания проверяются следующим кругом; другая схема — отказ |
| `pg_range.rngcanonical`, `rngsubdiff` | `type_function` | то же |
| Опорные функции (`pg_amproc`) семейств всех классов операторов типа (`opcintype`, любой метод доступа) и класса подтипа диапазона (`rngsubopc`), кроме семейств `pg_catalog` | `type_function` | то же |
| Операторы этих семейств (`pg_amop`) | `operator` и `operator_function` | существующие: оператор — `public` или `pg_catalog`; функция оператора не из `pg_catalog` — как функция выражения |
| `oprrest`, `oprjoin` операторов семейств и операторов `public`, названных в запросе | `type_function` | как у машинерии |
| `pg_cast.castfunc`, где тип — источник или цель | `function` | существующее: `public` или `pg_catalog` из списка basic |
| `CHECK` домена (`pg_get_expr(conbin, 0)`) | `domain` | существующее: текст проверяется как определение |

- **Почему `pg_catalog` в слотах машинерии — любая функция.** Встроенная машинерия типов `public` почти целиком состоит из функций вне списка basic: `enum_in`, `domain_in`, `array_in`, `range_in`, `btint4cmp`, `eqsel`, `scalarltsel`. Сигнатуру слота задаёт Postgres: `cstring`, `internal`, сравнение двух значений типа. Такую функцию вызывают только со значением типа, а не с текстом агента.
- **Функция приведения — строже.** Её сигнатура обычная (`text → T`), а аргумент — значение агента. Например, `CREATE CAST (varchar AS app_x) WITH FUNCTION pg_catalog.current_setting(text)` при `'app.jwt_secret'::varchar::app_x` читал бы настройку. Поэтому она проверяется как функция выражения. На 14 расширениях contrib в `public` приведений с функцией `pg_catalog` вне списка basic нет (§5).
- **Функции и операторы расширений** (`pg_depend`, `deptype = 'e'`) в строки не попадают. Машинерию типа расширения (citext, hstore, PostGIS) ставит скрипт расширения, в том числе в схему вне `public`: у Supabase это `extensions`. Её функцию вывода вызывает любое чтение колонки такого типа. Живьём без этого исключения `SELECT id FROM app_z` с колонкой `extensions.citext` отклонялся по `extensions.citextsend`, а с исключением проходит. Обёртка DBA над функцией чужой схемы членом расширения не бывает, пока её не добавят явно (`ALTER EXTENSION … ADD`). Это принятая граница доверия, она описана в README (§6).
- **Отвергнутая альтернатива — «запачканные» типы всей базы одним запросом и пересечение с семенами.** Семена нужны всё равно, а машинерия всех типов базы дороже машинерии замыкания семян. Тип схемы `secret` со своими функциями запачкан всегда, но в запрос агента он не попадает; в замыкании его проверка тоже не нужна.

## 4. Порядок и запросы

- **До `PREPARE`** — тот же запрос реализаций (`ALLOWED_IMPLEMENTATIONS_SQL`). Он получает семена `{types}` и `{relations}` (текст идентификаторов в кавычках), CTE `seeds` (плюс типы найденных функций, операторов, агрегатов) и CTE `_type_machinery`. Строки машинерии проверяются тем же `_check_rule_row`. Запрос теперь уходит, когда в SQL агента есть отношение или имя типа не из `pg_catalog`, а не только оператор или функция. Так `PREPARE` не выполняет функцию ввода, а `EXPLAIN` — вывод и свёртки.
- **После `PREPARE` и после всех `EXPLAIN`** — тот же запрос определений (`DEFINITION_DEPENDENCIES_SQL`): `_type_machinery` от колонок `relations` и `types`. Строки проверяются и помечаются как увиденные (`_seen_rows`), так что второе чтение их не повторяет. Так закрыты типы, которых в SQL агента нет: приведение внутри представления (`… WHERE 1::app_rd IS NOT NULL`), колонка базовой таблицы представления с `ORDER BY`.
- **Функция машинерии `public`** (`type_function`, `operator_function`, `function`) отмечается как реализация. Следующий круг `_check_catalog_names` проверяет её тело, умолчания и её типы, в пределах `_MAX_DEFINITION_DEPTH`.
- **Цена.** Новых запросов нет, кроме запроса реализаций у оператора без имён операторов и функций: `SELECT * FROM app_t` — пять запросов вместо четырёх, `EXPLAIN (GENERIC_PLAN) SELECT … FROM app_t WHERE $1 IS NULL` — семь вместо шести. `SELECT … WHERE id = 1` — по-прежнему пять.

## 5. SQL и стоимость

- Весь SQL — с `pg_catalog.` у каждого отношения, функции и типа и `OPERATOR(pg_catalog.…)` у каждого оператора. Новый SQL покрывает существующий тест квалификации (`_unqualified_names`). Схема `pg_catalog` — `'pg_catalog'::pg_catalog.regnamespace::pg_catalog.oid`.
- Множества — массивами через `unnest` (`_oid_set`): семена, замыкание (`machinery_set`). Рекурсия замыкания — одна CTE `type_closure` с `LATERAL` по пяти рёбрам.
- Живьём (оценка планировщика, `jit_above_cost` = 100000, время выполнения запроса):

| База | Запрос | До | После |
| --- | --- | --- | --- |
| 14 расширений contrib в `public`; 3 отношения, 14 колонок типов расширений, составной тип и массив | определения | 1683, 10 мс | 8057, 11 мс |
| то же | реализации | 284, 3 мс | 6686, 5 мс |
| типы волны: перечисление с приведением, базовый тип, класс операторов, домен, диапазон | определения | 1595 | 7463 |
| то же | реализации | 216 | 6113 |

- **Ложные отказы на расширениях.** С расширениями `citext`, `hstore`, `ltree`, `isn`, `cube`, `earthdistance`, `seg`, `pg_trgm`, `btree_gist`, `btree_gin`, `intarray`, `uuid-ossp`, `pgcrypto`, `lo` в `public` проходят 14 запросов: `ORDER BY`, `DISTINCT`, `GREATEST`, `UNION`, операторы `?`, `<@`, `=`, приведения к `text` и `jsonb`, `INSERT` литералов, составной тип и массив составного, представление. Приведений с функцией `pg_catalog` вне списка basic среди них нет.

## 6. Не входит

- (x) Тела PL/pgSQL и других процедурных языков: функция машинерии `public` на PL/pgSQL проходит, её тело непрозрачно, как у любой функции.
- (x) Машинерия встроенных типов, изменённая суперпользователем. Сюда входят:
  - приведение между двумя встроенными типами (`CREATE CAST (int4 AS text) WITH FUNCTION secret.f`);
  - член, добавленный в семейство `pg_catalog`;
  - класс операторов `public` для встроенного типа (`FOR TYPE int4`): его вызывают индекс и ограничение-исключение с этим классом.

  Типы `pg_catalog` проверка не раскрывает.
- (x) Функция, добавленная в расширение явно (`ALTER EXTENSION … ADD FUNCTION`): члены расширений в машинерии доверенные.
- (x) Неявное приведение к reg*-типу (поиск по имени при выполнении), функции преобразования кодировок (`CREATE CONVERSION`).
- (x) Схема оператора `USING` в ключе сортировки, collation и метода `TABLESAMPLE`: план печатает их без схемы.
- (x) `WITH CHECK OPTION` представлений.
- (i) Функции машинерии `pg_catalog` проверяются не по списку basic (§3). Функция приведения и функция оператора `public` проверяются по нему.

Рёбра замыкания и пропуск `pg_catalog`. Исключение членов расширений. Семена `to_regtype`/`to_regclass` и типы функций, операторов, агрегатов. Семена определений — `relation_set`, `types`, `pg_attribute`. Квалификация всего нового SQL (существующий `_unqualified_names`).
- **Юнит, `test_plan_guard.py`.**
  - Семена SQL агента (`'5'::app_t`, со схемой, составной тип, `INSERT` литерала, отношение со схемой) уходят в запрос реализаций до `PREPARE`, отказ — без `PREPARE`.
  - Типы `pg_catalog` семенами не становятся.
  - Строки машинерии из чтения определений отклоняются до `EXPLAIN`: `type_function` чужой схемы, `function` чужой схемы и `pg_catalog` вне списка basic, `operator_function`, оператор чужой схемы, `CHECK` домена.
  - `type_function` из `pg_catalog` проходит.
  - `type_function` из `public` проверяется по телу.
  - Существующие тесты, которые считали запросы реализаций или шаги журнала, учитывают первый запрос с семенами.
- **Интеграция, `test_plan_check.py`, бросающие функции.** Без проверки каждый запрос получил бы ошибку функции `secret` (проверено на коде до волны: 13 из 14 падают исключением функции, оценка селективности — «DID NOT RAISE»):
  - явное приведение и приведение присваивания;
  - вывод типа при `EXPLAIN VERBOSE`, ввод при `PREPARE`, ввод атрибута составного типа;
  - `ORDER BY`, `GREATEST` по колонке и по константам;
  - `CHECK` домена: прямое приведение, в представлении (колонка и скрытое в `WHERE`), подтип диапазона;
  - класс операторов колонки базовой таблицы представления;
  - оценка селективности оператора `public`.

  Ещё один тест: перечисление `public` (встроенная машинерия) проходит.

## 8. Изменения поведения (для заметок к PR)

- С `plan_check` отклоняется запрос, который доходит до типа (названного, типа колонки названного или заблокированного отношения, аргумента или результата функции или оператора `public`, типа из зависимостей определений — и вложенных в них), если машинерия этого типа вызывает функцию другой схемы (не члена расширения) или функцию `public`, которая не проходит проверки. Машинерия — это функции ввода-вывода, приведения, опорные функции и операторы классов операторов, оценка селективности, `canonical`/`subdiff`. Так же отклоняется запрос, если у приведения такого типа функция `pg_catalog` вне списка basic или `CHECK` домена вызывает такую функцию. Отказ приходит до `PREPARE` (типы SQL агента) или до `EXPLAIN` (заблокированные отношения и зависимости).
- Оператор `public`, одна из перегрузок которого (все перегрузки с именем) принимает или возвращает такой тип, отклоняет любое использование своего имени. Например, `public.=` над таким типом отклоняет любое `=`.
- Колонка такого типа отклоняет любой запрос к её отношению, даже если колонку он не читает. Домен с таким `CHECK` отклоняет и `SELECT`, хотя чтение `CHECK` не выполняет.
- Оператор `public`, названный в запросе, проверяется и по функциям оценки селективности (`RESTRICT`, `JOIN`).
- Запрос реализаций теперь уходит и для оператора без имён операторов и функций, если в нём есть отношение или имя типа: `SELECT * FROM app_t` — пять запросов вместо четырёх. Оба запроса каталога читают больше: оценка планировщика до ~8000 (порог JIT — 100000), выполнение до ~11 мс на базе с 14 расширениями.
- Функции и операторы расширений в машинерии типов доверенные — в том числе в схеме вне `public`.
